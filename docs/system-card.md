# System Card

## System Name
AI Security Chatbot

## Version
1.0.0

## Date
August 2026

---

## Components

| Component | Technology | Purpose |
|---|---|---|
| Frontend | React 18 + Vite | User interface, chat, document upload, security dashboard |
| Backend | Flask 3.x (Python) | API layer, request validation, orchestration |
| Language Model | Llama 3.2 via Ollama | Natural language generation |
| Embedding Model | all-MiniLM-L6-v2 (sentence-transformers) | Converts text to vectors for retrieval |
| Vector Database | ChromaDB (persistent, local) | Stores and retrieves document embeddings |
| PDF Processor | pypdf | Extracts and chunks text from uploaded PDFs |

---

## Intended Use

- Local, offline document-aware question answering.
- Security research and policy document analysis.
- Demonstration of RAG architecture with security testing.

---

## Limitations

- The model may hallucinate facts not present in uploaded documents.
- RAG retrieval is limited to the top 5 most relevant chunks per query.
- The system is not designed for multi-user or production deployment without additional hardening.
- The system prompt is a guideline, not a hard constraint — sufficiently adversarial prompts may bypass it.
- Llama 3.2 is a general-purpose model; it has no specialised security domain training.

---

## Security Controls

| Control | Implementation |
|---|---|
| Input validation | All Flask routes validate message and file inputs |
| File type enforcement | Only `.pdf` files accepted at upload |
| File size limit | 20 MB maximum |
| Message length limit | 20,000 characters maximum |
| Prompt injection resistance | System prompt instructs model not to follow user-injected instructions |
| Automated security testing | 20 tests across injection, leakage, RAG, and chaos categories |

---

## Out of Scope

- Multi-user authentication and access control.
- Rate limiting and DDoS protection.
- Production TLS / HTTPS.
- Audit logging of user interactions.
